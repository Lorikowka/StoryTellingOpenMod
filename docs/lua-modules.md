# Библиотеки Lua в сюжетах

Начиная с alpha.66, сценарий в `ST/scripts/` может загружать вспомогательный Lua-файл через `require("characters.guide")`. Этот вызов ищет только `ST/scripts/characters/guide.lua`. Вспомогательные файлы размещаются во вложенных папках; числовые файлы сценариев по-прежнему лежат прямо в `ST/scripts/`.

Пример: скопируйте `examples/story_scripts/characters/guide.lua` в `ST/scripts/characters/guide.lua` и `examples/story_scripts/900051.lua` в `ST/scripts/900051.lua`. Затем выполните `/script reload 900051.lua` и `/script start 900051`.

Имя модуля содержит только латинские буквы, цифры и подчёркивание в каждом сегменте, разделённом точками. Сегмент начинается с буквы или подчёркивания. Путь `..`, абсолютный путь, обратная косая черта и ссылка вне `ST/scripts/` отклоняются. Символические ссылки, ведущие за пределы каталога, тоже отклоняются. Один файл может загрузить до 64 модулей размером не больше 256 КиБ каждый. Повторный `require` внутри одной загрузки сценария возвращает уже полученное значение; циклический импорт даёт ошибку.

Модули исполняются при загрузке сценария, поэтому используйте их для таблиц, функций и объявлений. Действия в мире выполняются только после запуска сценария. Стандартные `package`, `dofile` и `loadfile` остаются недоступными. Изменение модуля подхватится при `/script reload <сценарий.lua>` или общем `/script reload`; уже работающий экземпляр сценария продолжит прежнее определение.

Это первый шаг к библиотекам NPC. Текущий `npc{...}` объявляет NPC конкретного сценария. Отдельные шаблон и экземпляр персонажа, политика их сохранения и манифест сюжетного пакета пока не реализованы.

Загрузчик ограничивает пути и число импортируемых файлов, но пока не устанавливает лимит процессорного времени и памяти для самого Lua-кода. Чужие сюжетные пакеты до появления таких ограничений следует считать доверенным кодом сценария.
