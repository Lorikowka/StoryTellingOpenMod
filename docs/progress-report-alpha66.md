# Отчёт о состоянии Storytelling — alpha.66

Дата сверки: 16 ноября 2026 года. Этот документ описывает состояние ветки `feature/safe-lua-modules` и рабочего MDK, а не гарантии для ветки `main` или произвольной сборки Minecraft. Актуальная очередь работ находится в [плане развития](engine-expansion-plan.md); подробная сверка архитектурной концепции с кодом — в [разборе alpha.65](architecture-review-alpha65.md).

## Что уже сделано

### Основа проекта и сценарии

- Восстановленный проект приведён к структуре Forge MDK для Minecraft 1.20.1. Сборка работает на JDK 17; рабочая версия — `20.1.34-update-lua-alpha.66`.
- Пользовательские главы загружаются из `ST/scripts/` как Lua-файлы с числовым ID. Их можно проверять через `/script validate`, запускать через `/script start <id>` и перезагружать целиком либо по одному файлу через `/script reload [файл.lua]` без пересборки мода.
- Lua API включает части и якоря, реплики и выборы, ожидание F8, чата, позиции и предметов, переменные и условные переходы, звук, частицы, экранные эффекты, действия с предметами, камерой и квестами. Активный сценарий сохраняет шаг и восстанавливается после перезахода; завершённый сценарий удаляется из списка активных, а история диалога остаётся доступной.
- `alpha.66` добавляет контролируемый `require("characters.guide")` для библиотек внутри `ST/scripts/`. Есть кэш на одну загрузку, обнаружение циклов, проверка пути и размера файла. Пример — `900051.lua` и `characters/guide.lua`; полное описание — в [руководстве по модулям](lua-modules.md).

### NPC, постановка и интерфейс

- Сценарий может объявить NPC через `npc{key=..., model=..., name=..., width=..., height=...}` и работать с ним методами появления, движения, взгляда, анимации, взаимодействия с блоком, удаления и пролёта камеры. Старые функции `npc_*` сохранены для существующих глав.
- Для glTF-моделей поддерживаются анимации из файла модели, настраиваемый хитбокс и портрет из группы `Head`. Проверены поворот головы и тела, наземный маршрут NPC и взаимодействие с блоком. Для рычага есть действие, устанавливающее заданное состояние без повторного переключения при восстановлении.
- Диалог с выбором, история реплик, уведомления об изменении квеста и `hint(text[, ticks])` используют интерфейс мода. Квестовый журнал поддерживает статусы, задачи, один уровень подзадач, скрытые подзадачи, автоматическое завершение и сохранение выбранной вкладки. Журнал открывается клавишей J.
- В игре доступны `/storyedit` для Lua-файлов и `/storyblocks` для визуального составления сценария. Блочный редактор уже умеет выбор, флаги и переходы вперёд; он пока не является полноценной средой для произвольного Lua.

### Очистка и совместимость

- Удалены неиспользуемые встроенные Java-главы, исключённые из компиляции исходники, старый refmap, 75 незарегистрированных Bedrock-анимаций и тестовый сценарий `113377`. Подробный учёт и ограничения — в [аудите наследия](legacy-cleanup-audit.md).
- Оставлены служебные Java-сценарии и ресурсы, чьи связи со старыми мирами ещё не проверены. Команды фильтруют пустые категории сценариев. ID предметов, обнаруженные в старом сохранении, сохранены для совместимости.
- В рабочем MDK исходные файлы обновлены до alpha.66 с резервной копией перед заменой. Пример `900051` и библиотека персонажа положены в `run/ST/scripts/`.

## Ограничения текущей версии

- Lua строит последовательность действий при загрузке файла; игровой исполнитель по-прежнему использует `ScriptPerformer`. Новый самостоятельный runtime и параллельные Lua-ветки ещё не реализованы.
- `npc{...}` относится к конкретному сценарию. Повторно используемые NPC Template/Instance и постоянное состояние персонажа между независимыми сценами ещё не реализованы.
- `require` контролирует расположение и размер импортируемых файлов, но пока не ограничивает процессорное время и память самого Lua-кода. Стандартные `package`, `dofile` и `loadfile` остаются недоступными.
- Квестовый журнал хранит прогресс на уровне мира. Отдельная политика прогресса для каждого игрока и миграция будущих форматов сохранений требуют проектирования.
- Происхождение всех оставшихся классов, ресурсов и сторонних компонентов ещё не проверено. `mod_license=All Rights Reserved`; менять лицензию до такого аудита рано.

## Следующие действия

1. Проверить обновление библиотеки: изменить `name` в `characters/guide.lua`, выполнить `/script reload 900051.lua` и повторно запустить `900051`. Имя NPC и подпись говорящего должны измениться без пересборки JAR; текст реплики останется прежним.
2. Описать формат сюжетного пакета, манифест и версию Lua API, сохранив работу старых числовых файлов без манифеста.
3. Добавить отдельные шаблон и экземпляр NPC, затем правила долговременного сохранения состояния персонажей.
4. Спроектировать контракт нового исполнителя и переносить действия по частям с регрессионными проверками. После этого развивать параллельное исполнение, инструменты автора и очистку наследия.

Подробная последовательность и критерии находятся в [актуальном плане](engine-expansion-plan.md). Изменения ведутся отдельными ветками; успешную сборку и игровую проверку отмечаем раздельно.
