# Повторение действий Lua после прерывания

`ScriptPerformer` сохраняет индекс действия, но игровой мир, инвентарь игрока и данные сценария записываются в разные места. Таблица описывает текущее поведение; она не обещает атомарность при аварийном завершении процесса.

| Действие | Текущая защита | Оставшийся риск |
| --- | --- | --- |
| `var_set` для `script` и `scene` | Повторная запись того же значения. | После перемотки автор должен сам решить, нужно ли очистить область. |
| `var_set` для `world`, `player`, `npc:<key>` | Повторная запись того же значения. | Сохранение мира и индекса шага не является одной транзакцией. |
| `npc_state_migrate` | Переносит только недостающие значения, удаляет старый ключ; повторный вызов безопасен. | Сущность и позиция NPC не мигрируют. |
| `give_item` | Квитанция в данных игрока по токену запуска и индексу действия; после выдачи вызывается сохранение игрока. | Авария между выдачей и записью квитанции всё ещё может повторить предмет. |
| `npc_set_lever` | Проверяет требуемое состояние блока до нажатия. | Если блок заменён или выгружен, действие выдаёт ошибку. |
| `npc_set_door` | Проверяет состояние двери до нажатия и после него. | Работает с дверью, которую игрок может открыть рукой; закрытая железная дверь не примет такое нажатие. |
| `npc_set_trapdoor` | Проверяет состояние люка до нажатия и после него. | Работает с люком, который игрок может открыть рукой; железный люк не примет такое нажатие. |
| `npc_use_block`, `npc_try_use_block`, `npc_approach_use_block` | Для двух последних есть маркер завершения в сценарии; подход имеет предел ожидания. | Произвольная кнопка, дверь или механизм может сработать повторно после аварии до сохранения маркера. |
| `play_sound`, `particle`, `particle_here` | Маркер в сценарии подавляет повтор после сохранения. | После аварии до сохранения маркера звук или частица могут повториться. |
| `camera_shot`, `camera_fly_npc` | Остановка освобождает камеру. | После загрузки текущий полёт может начаться заново. |
| `npc_spawn` | Сохранённый NPC привязывается к репозиторию при восстановлении. | Переименование ключа меняет ID сущности; это не покрыто миграцией переменных. |
| `story_engine` | Передаёт вызов внешнему адаптеру. | Идемпотентность зависит от конкретной операции другого мода. |

Для новой истории предпочтительны команды с заданным конечным состоянием, например `npc_set_lever(..., true)` или `npc_set_door(..., true)`. Для произвольного взаимодействия с блоком, у которого нет читаемого состояния, гарантия «ровно один раз» требует квитанции в том же сохранении, что и сам эффект, либо поддержки со стороны блока. Пример `900057.lua` открывает деревянную дверь, повторяет установку того же состояния и закрывает её; перед запуском поставьте дверь нижним блоком в `3 -59 9`. Следующая реализация должна добавить другие специализированные операции там, где конечное состояние можно проверить, и тестировать аварийное восстановление отдельно от обычного перезахода.

Пользователь проверил `900057.lua` в игре 18 ноября 2026 года после замены обычного жителя на модельного NPC. Проверка подтверждает обычное последовательное выполнение; аварийное прерывание между изменением блока и сохранением шага остаётся непроверенным.

Пользователь также подтвердил обычное выполнение `900058.lua` с деревянным люком. Следующая проверка: сохранить мир между открытием и закрытием люка, вернуться в него и убедиться, что открытие не повторяется. Это проверяет восстановление после штатного выхода. Аварийное завершение требует отдельного тестового мира и контролируемой точки прерывания; не следует считать обычный выход эквивалентом аварии.
