# Контракт исполнения сценария

Этот документ разделяет действующее поведение `ScriptPerformer` и правила для следующего исполнителя. Новый исполнитель пока не включён: Lua-сценарии продолжают работать через существующий `ScriptPerformer`.

## Сейчас

- `Performer.tick()` вызывает `tick()` текущего действия, затем `isDone()`. Завершённое действие продвигает `actionIndex`. `shouldContinue()` может разрешить обработку следующих действий в том же тике.
- Ожидания (`wait_f8`, чат, позиция, предмет) остаются на текущем индексе до выполнения условия. Внешние события передаются действиям через `handleEvent()`.
- При сохранении записываются `actionIndex`, имя этапа, флаги сценария и данные активного Lua-запуска. Для Lua также сохраняется отпечаток определения. Изменённый сценарий с несовместимым отпечатком не возобновляется на старом индексе.
- При остановке вызывается `onScriptStop()` у действий; камера освобождается там, где действие реализует этот вызов. При переходе к якорю действия получают `reset0()` или ускоренное продвижение.
- `alpha.80` добавляет версионированный `activeAction` со снимком состояния и именем класса действия. Сначала этот формат использовали активная реплика и ожидание F8; старые поля реплики из `alpha.79` читаются как запасной вариант. В `alpha.81` к нему добавлены оставшиеся тики `wait_ticks` и факт принятого сообщения `wait_chat` вместе с его короткой задержкой. Время ожидания не идёт, пока мир закрыт. `alpha.84` сохраняет факт начала `camera_shot` и `camera_fly_npc`: прерванный кадр после загрузки пропускается, чтобы не показывать его повторно. Остальные действия с побочным эффектом должны иметь собственную политику повторения.
- `alpha.85` сохраняет прошедшие тики и завершение маршрута `EntityPathfinderAction`. После загрузки незавершённый маршрут строится от сохранённого положения NPC; прежний объект навигатора не переносится между мирами.
- `alpha.86` отменяет текущее действие перед переходом к другому индексу. Действие движения NPC удаляет навигационное поведение при завершении и отмене, чтобы маршрут не продолжался после скачка к якорю.
- `alpha.87` направляет авторскую команду `/script goto` для Lua через переход без ускоренного исполнения пропущенных шагов. Это не переносит NPC в точку назначения при отмене маршрута.

## Целевой интерфейс

| Событие | Требование |
| --- | --- |
| `start(context)` | Вызывается один раз при первом входе в шаг; повторное восстановление определяется стабильным ключом шага. |
| `tick(context)` | Возвращает `WAITING`, `DONE` или ошибку с причиной; не скрывает ошибку под бесконечным ожиданием. |
| `event(context, event)` | Принимает только события, относящиеся к активному шагу и его исполнителю. |
| `save()` / `restore(data)` | Сохраняет версию состояния шага и данные, нужные для продолжения без повторного эффекта. |
| `cancel(reason)` | Освобождает временную камеру, навигацию NPC, GUI и подписки; допускает повторный вызов. |

Ключ действия должен включать ID сценария, токен запуска и стабильный идентификатор шага. Индекс в текущем списке можно использовать лишь пока отпечаток определения совпадает. Переход к якорю и перезагрузка файла обязаны проходить через тот же механизм отмены. Если внешнее действие нельзя повторить безопасно, новый исполнитель должен остановить сценарий с диагностикой, а не выполнять его второй раз молча.

Перед переносом Lua на новый исполнитель нужны контрольные сценарии для ожиданий, перезахода, отмены камеры и навигации NPC, выбора, миграции шага и каждого побочного эффекта из [аудита восстановления](lua-side-effect-recovery.md). Параллельные ветки добавляются после последовательного исполнения: камера и один NPC могут принадлежать только одной активной ветке либо иметь явно заданный порядок арбитража.
