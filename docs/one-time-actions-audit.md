# Одноразовые действия Lua-сценария

`give_item` в `alpha.60` использует ключ из идентификатора запуска сценария и номера действия. Квитанция записывается в данные игрока вместе с инвентарём, после чего сервер сохраняет игроков. Если состояние самого сценария отстало от сохранения игрока, восстановленный шаг увидит квитанцию и не выдаст предмет снова. Новый запуск получает новый ключ.

Сохранение игрока и мира не является единой транзакцией. При полном инвентаре оставшийся предмет выпадает в мир, и его сохранение отдельно от квитанции не гарантировано при аварийном завершении процесса. Это ограничение нужно учитывать при выдаче редких предметов. Существующие сохранения, сделанные до появления идентификатора запуска, получают новый идентификатор при загрузке.

Остальные действия рассмотрены отдельно:

| Действие | Состояние |
| --- | --- |
| `play_sound`, `spawn_particle` | Визуальные эффекты; повтор после сбоя допустим, внутри текущего запуска защищены маркером действия. |
| `teleport_player` | Повторное перемещение в ту же точку не создаёт нового ресурса. |
| `npc_use_block`, `npc_approach_use_block` | Может повторно переключить рычаг после прерывания между нажатием и сохранением сценария. Для рычагов используйте `npc_set_lever` с явным целевым состоянием. Кнопки и произвольные блоки всё ещё требуют отдельного решения. |
| `npc_set_lever` | Проверяет текущее состояние рычага и нажимает его только при несовпадении с желаемым. Повторное выполнение сходится к тому же состоянию. |
| `npc_set_door` | Проверяет открытость двери и нажимает её только при несовпадении с желаемым состоянием. Нужна деревянная дверь и доступный для NPC блок. |
| `quest_*` | Состояние журнала сохраняется с миром; уведомления о повторном применении должны зависеть от реального изменения записи. |
