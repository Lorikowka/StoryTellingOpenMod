# Сценарии Storytelling на Lua

Короткое руководство для **Storytelling 1.20.1**. Lua уже встроен в мод: для изменения текста не нужно ставить другой мод или пересобирать JAR. Примеры ниже относятся к текущему API Storytelling, а не к HollowEngine.

## Быстрый старт

1. Запустите Minecraft с Storytelling. Мод создаст `ST/scripts/`, `ST/logs/`, `ST/assets/models/` и `ST/assets/textures/` в папке игры. Примеры `900001.lua` и `s7.lua` появятся в `ST/scripts/`. При `gradlew runClient` это `merged_mdk/run/ST/scripts/`.
2. Зайдите в мир и введите `/script start 900001`.
3. Когда появится подсказка, нажмите **F8**.

Существующие файлы мод не перезаписывает. Для своего сценария скопируйте `900001.lua` в `900002.lua`, измените первую строку на `story(900002)` и выполните `/script reload`. Запуск: `/script start 900002`.
При первом запуске после обновления мод копирует существующие `.lua` из прежней папки `config/storytelling/stories/` в `ST/scripts/`. Исходные файлы остаются на месте; при совпадении имён побеждает файл в `ST/scripts/`. Позже удалённые из `ST/scripts/` сценарии не появляются снова из прежней папки.
После добавления или изменения Lua-файла используйте `/script reload`: новые запуски возьмут новую версию файла. Уже работающие сценарии продолжат прежнюю версию.
Перед запуском можно выполнить `/script validate`: команда проверит все `.lua` в `ST/scripts/`, покажет ошибки синтаксиса, несовпадение числового имени файла с `story(id)`, повторяющиеся ID и конфликты с Java-сценариями. Проверка не запускает и не перезагружает сценарии; при большом числе ошибок в чате выводятся первые десять.

## Минимальный сценарий

Файл `900002.lua`:

```lua
story(900002)

part("main")
speaker(0, "Проводник")
speech(0, "Привет. Это мой первый сценарий.")
warning("Нажми F8, чтобы продолжить")
wait_f8()
speech(0, "Отлично, идём дальше.")
```

Имя файла и число в `story(...)` должны совпадать. `story(...)` пишется один раз до первой `part(...)`; непустая часть `main` обязательна.

## Якорные точки

Поставьте `anchor("chapter_two")` в нужном месте после `part("main")`. Для перехода в уже работающем сценарии: `/script goto 900006 chapter_two`. Для запуска или перезапуска с этой точки: `/script start 900006 chapter_two`. Переход пропускает предшествующие действия исполнителя; некоторые действия при этом выполняют ускоренный переход, поэтому проверяйте эффект в игровом мире.

## Действия

| Вызов | Что делает |
| --- | --- |
| `story(id)` | Задаёт положительный числовой ID сценария. |
| `part("main")` | Начинает основную часть. Действия ниже идут по порядку. |
| `anchor("name")` | Именованная точка сценария; имя уникально в файле. |
| `speaker(id, "имя")` | Задаёт имя говорящего для реплик с этим ID. |
| `speaker_npc(id, key)` | Назначает говорящим объявленного NPC и берёт портрет из его glTF-модели. Если `speaker(id, "имя")` совпадает с именем NPC с glTF-моделью, портрет подставится автоматически. |
| `speech(id, "текст")` | Показывает реплику говорящего. |
| `warning("текст")` | Показывает подсказку игроку. |
| `wait_f8()` | Ждёт нажатия F8. |
| `wait_pos(x, y, z, radius, dimension, ignore_y)` | Ждёт, пока игрок подойдёт к точке. Последние два аргумента необязательны: по умолчанию `minecraft:overworld` и `false`. |
| `teleport_player(x, y, z, dimension, yaw, pitch)` | Перемещает игрока в точку. Измерение можно опустить; углы поворота указываются вместе, иначе сохраняется текущий взгляд. |
| `npc(key, type, name)` | Объявляет NPC до первой `part(...)`, например `npc("guide", "minecraft:villager", "Проводник")`. |
| `npc_model(key, file, name)` | Объявляет сюжетного NPC с моделью `.glb` или `.gltf` из `ST/assets/models/`, например `npc_model("guide", "guide.gltf", "Проводник")`. |
| `npc_hitbox(key, width, height)` | Задаёт размер хитбокса glTF-NPC в блоках до первой `part(...)`. Ширина 0.1–8, высота 0.1–16; по умолчанию 0.6 × 1.8. |
| `npc_spawn(key, x, y, z, dimension)` | Ставит объявленного NPC в точку; измерение необязательно. |
| `npc_move(key, x, y, z, speed, dimension)` | Ведёт ходящего NPC к точке через поиск пути по блокам и ждёт завершения. Скорость: больше 0 и не больше 1; измерение необязательно. Для далёких или сложных маршрутов добавьте промежуточные точки отдельными вызовами. Если путь не завершился за 120 секунд, NPC выгрузился или остановился далеко от цели, сценарий выдаёт понятную ошибку. |
| `npc_use_block(key, x, y, z, dimension)` | NPC взаимодействует с блоком по целочисленным координатам через серверный механизм использования блока игроком. Измерение необязательно. Сначала подведите NPC вызовом `npc_move` на расстояние до 4,5 блока. Подходит для ванильных кнопок, рычагов и открываемых игроком дверей; блоки других модов зависят от поддержки подставного игрока. При невозможности использования сценарий выдаёт ошибку с координатами. |
| `npc_try_use_block(key, x, y, z, result_name, dimension)` | Пробует нажать блок и записывает `true`/`false` в переменную `result_name` для `var_if`. При недоступном блоке или NPC записывает `false`; ожидание появления NPC ограничено 10 секундами. Измерение необязательно. |
| `npc_approach_use_block(key, x, y, z, result_name, dimension)` | Пытается подвести модельного NPC к свободному соседнему блоку, затем нажать цель. Результат `true`/`false` сохраняется в переменной; неудачный путь завершается `false`. Измерение необязательно. |
| `npc_animation(key, clip, mode)` | Запускает клип из `.glb`/`.gltf` в режиме `once` (один раз, затем вернуть исходную позу), `hold` (один раз и замереть на последнем кадре) или `loop` (цикл; режим по умолчанию). `"auto"` выбирает `idle`/`walk`; по умолчанию цикл. Только для `npc_model`. |
| `npc_look(key, "player", mode)`, `npc_look(key, x, y, z, mode)`, `npc_look(key, "none")` | Направляет взгляд модельного NPC на игрока или точку. Режим `head` вращает только голову (до 60°), `body` разворачивает корпус до цели, `auto` сначала голову и при превышении 60° разворачивает корпус полностью. Режим необязателен, по умолчанию `auto`; `none` выключает слежение. Модель должна иметь группу `Head` с дочерними узлами. |
| `var_set(name, value, scope)` | Записывает строку, число или boolean во время исполнения. Область `script` (по умолчанию) живёт до завершения сценария; `world` доступна всем сценариям мира, `player` привязана к UUID игрока. |
| `var_if(name, value, yes_anchor, no_anchor, scope)` | Во время исполнения сравнивает сохранённое значение в области `script`, `world` или `player` и переходит к одному из двух якорей. Область необязательна, по умолчанию `script`. Оба якоря должны находиться ниже в той же части. |
| `goto_anchor(name)` | Переходит к следующему якорю в той же части или к `final` для завершения сценария. Не выполняет пропущенные действия. |
| `play_sound(id, volume, pitch)` | Проигрывает зарегистрированный звук у игрока. Громкость 0–4, высота 0.5–2; параметры необязательны и по умолчанию равны 1. |
| `give_item(id, count)` | Выдаёт игроку зарегистрированный предмет; количество 1–64, по умолчанию 1. Если инвентарь полон, остаток выпадает рядом. |
| `spawn_particle(id, x, y, z, count)` | Отправляет игроку 1–200 простых зарегистрированных частиц вокруг указанной точки в его измерении. Если игрок дальше 512 блоков, действие ждёт его приближения. |
| `spawn_particle_here(id, count)` | Отправляет 1–200 частиц примерно в двух блоках перед взглядом игрока; удобно для эффекта, который должен быть виден независимо от координат сцены. |
| `camera_shot(x, y, z, yaw, pitch, ticks)` | Показывает фиксированную точку камерой на 2–72000 тиков и возвращает обзор игроку. Не меняет игровой режим. При остановке сценария камера возвращается сразу; после перезахода незаконченный кадр начинается заново. Пока рассчитано на одного локального игрока. |
| `choice(name, prompt, option1, option2, ...)` | Показывает вопрос и 2–6 нажимаемых ответов в игровом чате. Нажатие подставляет номер в строку чата; отправьте его Enter. Выбор сохраняется в переменной сценария `name` как `"1"`, `"2"` и т. д. После перезахода ожидание выбора восстанавливается. |
| `choice_if(name, prompt, option1, option2, ...)` | Как `choice`, но каждый ответ задаётся таблицей `{ text = "Ответ", when = "flag", equals = "true", scope = "script" }`. Условие проверяется во время показа и при отправке номера. `scope` может быть `script`, `world` или `player`; без `when` ответ виден всегда. Нужен хотя бы один безусловный ответ. Номера соответствуют порядку таблиц и не меняются, если часть ответов скрыта. |
| `npc_wait_interact(key)` | Ждёт взаимодействия игрока с NPC. |
| `npc_remove(key)` | Убирает NPC со сцены. |
| `wait_ticks(20)` | Ждёт указанное число игровых тиков (20 тиков ≈ 1 секунда). |
| `wait_chat("готово")` | Ждёт сообщение игрока с указанным словом. |
| `wait_flag("имя")` | Ждёт сюжетный флаг Storytelling. |
| `think("текст")` | Показывает мысль через существующий интерфейс Storytelling. |
| `blackout(20)` | Затемняет экран на указанное число тиков. |
| `flash(20)` | Показывает белую вспышку на указанное число тиков. |

## NPC с моделью glTF

Проверка взгляда: запустите `/script reload`, затем `/script start 900013` и обойдите Реги́ра по кругу. После F8 взгляд вернётся вперёд.

Контрольная глава для выбора и NPC находится в `ST/scripts/900020.lua`. Запустите `/script reload` и `/script start 900020`. После реплики нажмите F8, выберите `1` или `2` в обычном чате. Для проверки сохранения выйдите в меню на экране выбора, войдите снова и отправьте номер. Ветка `1` ведёт NPC к точке `5.5 -60 9.5`, ветка `2` завершает главу на месте.

`/script inspect <id>` показывает текущий шаг, последний якорь, действие и сохранённые переменные активного сценария. Это удобно сразу после перезахода, чтобы проверить восстановление.

Поддерживаются **glTF 2.0** в формате GLB (`.glb`) и JSON (`.gltf`). Для первого опыта удобнее GLB с текстурами внутри; `.gltf` также подходит, если все внешние буферы и текстуры находятся внутри `ST/assets/` (или включены в модель как data URI). Положите модель в `ST/assets/models/`, например `guide.gltf`. Модель может содержать несколько анимаций; отдельный файл для каждого клипа не нужен. С этой версии для запуска Storytelling требуется мод **GFBS: glTF 1.5.1** рядом с HammerLib и HammerAnimations. Последние два пока остаются нужны старым сущностям Storytelling.

Для портрета в сюжетном чате назовите группу головы `Head`. В портрет попадут все её дочерние меши, включая лицо, волосы и головной убор. Для моделей, где голова существует только как кость (например, `b_Head_05`), выбираются полигоны, привязанные к этой кости. Результат кэшируется клиентом; если подходящей головы нет, показывается стандартная иконка. `speaker_npc(id, key)` явно связывает говорящего с NPC; обычный `speaker(id, "имя")` тоже использует портрет, если имя совпадает с именем NPC с glTF-моделью.

```lua
story(900008)
npc_model("guide", "guide.glb", "Проводник")
npc_hitbox("guide", 0.6, 1.8)

part("main")
npc_spawn("guide", 3.5, -60, 2.5)
speaker_npc(1, "guide")
speech(1, "Привет!")
npc_animation("guide", "wave", "hold")
wait_f8()
npc_animation("guide", "auto")
npc_move("guide", 6.5, -60, 2.5, 0.2)
```

`npc_animation("guide", "wave", "once")` играет клип один раз, затем возвращает модель в исходную позу; `"hold"` оставляет её в позе последнего кадра; `"loop"` повторяет клип. Если третий аргумент пропущен, используется `"loop"`.

При `auto` рендерер играет `walk`, пока NPC выполняет сюжетное перемещение, и `idle` в покое. Имена клипов должны точно совпадать с `walk` и `idle`; если нужного клипа нет, NPC остаётся в исходной позе. Путь модели задаётся относительно `ST/assets/models/`; выход из этой папки отклоняется. Внешние ресурсы glTF разрешаются внутри `ST/assets/`, но для первого опыта удобнее встроить текстуры в GLB. После добавления или изменения Lua-файлов выполните `/script reload` либо перезапустите клиент. Изменения самого файла модели подхватываются во время игры; после изменения внешних буферов или текстур перезапустите клиент.

Можно добавить `part("setup")` перед `part("main")`. Сейчас её действия идут перед `main` в **одной** последовательности. Другие имена частей можно записать в файл, но исполнитель Lua их пока не запускает.

## Обычный Lua

Переменные, функции и циклы помогают составить действия:

```lua
story(900003)
part("main")

local lines = { "Первая реплика", "Вторая реплика" }
speaker(0, "Голос")
for _, line in ipairs(lines) do
    speech(0, line)
end
```

Цикл выполняется при **загрузке файла**, создавая две реплики. Он не повторяется во время игры. Доступ к Java, файлам и сети из сценария не предоставляется; `require`, `dofile` и `loadfile` отключены.

## Возможности и ограничения

Сейчас доступны реплики, мысли, подсказки, ожидание F8, позиции игрока, времени, сообщения чата и флага, а также простые эффекты экрана. Сценарий использует существующий исполнитель и сохранение Storytelling. Время для `wait_ticks`, `blackout` и `flash` должно быть от 1 до 72000 тиков.

Для перехода между сценами можно написать `wait_pos(-34.5, 56, -9.5, 1.0, "minecraft:overworld", true)`. При `ignore_y = true` высота игрока не учитывается. Проверка выполняется во время игры, а не при чтении Lua-файла.

Телепортация: `teleport_player(-51.5, 56, 6.5, "minecraft:overworld", -180, 0)`. Если поворот менять не нужно, пишите только первые три аргумента или четыре с измерением.

Синтаксис HollowEngine нельзя переносить в Storytelling без адаптации. Для NPC, выборов, условий, звука и частиц используйте вызовы из таблицы выше. Управление камерой и стадии игрока пока не входят в Lua API Storytelling. Старые Java-сценарии мода работают независимо от Lua API.

Порядок переноса присланных Kotlin-сценариев и функций Story Engine: [lua-porting.md](lua-porting.md).

## Необязательный адаптер Story Engine

Если в профиле установлен **совместимый с Minecraft 1.20.1** Story Engine, Lua может добавить в последовательность его квестовые вызовы:

```lua
quest_create("routine_work", "Работа", "Описание")
quest_task("routine_work", "exit", "Выйти из комнаты")
quest_start("routine_work")
quest_task_complete("routine_work", "exit")
quest_complete("routine_work")
```

Дополнительно доступны `quest_edit(id, description)`, `quest_reset(id)`, `quest_fail(id)` и `quest_notify(title, message)`. Вызовы выполняются тогда, когда до них доходит сценарий, а не при чтении файла. Без Story Engine сценарии, не использующие эти функции, работают обычно; сценарий с вызовом адаптера сообщит об отсутствующем API во время выполнения. Найденный `story_engine-1.2.10.jar` собран для Minecraft **1.19.2** и не подходит для профиля 1.20.1.

## Если сценарий не запускается

- `Скрипт ... не найден`: проверьте папку, имя файла и ID внутри `story(...)`, затем перезайдите в мир.
- Ошибка загрузки: откройте `logs/latest.log` и найдите `Cannot register Lua story` с путём файла.
- Сценарий не продолжается: после `wait_f8()` нажмите F8.
- `/script environment` показывает общее число сценариев. Строка `Scripts loaded` в журнале отдельно сообщает число Lua-сценариев.

ID существующего Java-сценария Lua-файлом заменить нельзя. Исключение — `s7.lua`: его читает старый Java-сценарий S7. Он не регистрируется как отдельный числовой Lua-сценарий; если файл удалить, S7 использует встроенную копию.

**Сохранение:** порядок действий важен. Движок сохраняет отпечаток разобранного сценария вместе с текущим шагом. Если действия или объявления NPC изменились, незавершённый сценарий не возобновляется на чужом шаге: `/script inspect <id>` покажет причину, а старое сохранение останется на диске. Верните прежнюю версию Lua-файла для продолжения либо явно запустите сценарий заново. Правки комментариев и пробелов отпечаток не меняют. Сохранения, созданные до `alpha.29`, ещё не имеют отпечатка и загружаются по прежним правилам.

Активные сценарии сохраняются в данных мира и возвращаются после перезапуска. Состояние записывается при сохранении мира; для сценария, который раньше не имел `@SaveOnClose`, предыдущий прогресс восстановить задним числом нельзя.
Номер текущего действия теперь тоже сохраняется. Завершённый Lua-сценарий удаляется из списка активных. Старые сохранения Lua без номера действия пропускаются при загрузке, чтобы реплики не воспроизводились повторно.

**История диалогов:** нажмите **Home**, чтобы открыть сюжетный чат. Он доступен после завершения сценария и повторного входа в мир. История хранится в `.storytelling/chat_history.dat` внутри папки мира и пополняется репликами Lua и сообщениями сюжетного чата. Реплики, показанные до версии `20.1.34-update-lua-alpha.1`, в новый файл не переносятся.
