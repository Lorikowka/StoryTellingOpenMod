# Состояние Lua-сценариев

`var_set(name, value, scope)` и `var_if(name, value, yes_anchor, no_anchor, scope)` поддерживают пять областей:

| Область | Запись | Срок хранения |
| --- | --- | --- |
| Сценарий | `script` | Сохранённый активный запуск сценария |
| Сцена | `scene` | Текущий запуск до `scene_reset()`; восстанавливается при перезаходе |
| Мир | `world` | Мир после завершения сценария |
| Игрок | `player` | Игрок по UUID в этом мире |
| NPC | `npc:<key>` | Экземпляр NPC по `lua_<story_id>_<key>` в этом мире |

Для объекта NPC доступны короткие вызовы `npc:state_set(name, value)` и `npc:state_if(name, value, yes_anchor, no_anchor)`. Они равнозначны `var_set(..., "npc:<key>")` и `var_if(..., "npc:<key>")`. Пример `900054.lua` записывает `met=yes` для `npc:persistent_guide`. После завершения сценария и повторного входа в мир новый запуск `900054` выбирает реплику о прошлой встрече. Другой ключ NPC получает отдельные значения. Старый формат сохранения без раздела `npcs` читается с пустым состоянием NPC; переменные мира, игрока и сценария остаются на прежних местах.

`scene_reset()` очищает только переменные `scene`. Сценарий может поставить этот вызов в начале новой сцены; переменные `script` остаются до завершения запуска. Оба вида переменных активного запуска восстанавливаются после перезахода. После завершения сценария они удаляются вместе с ним.

Пример `900055.lua` проверяет переход: после первой реплики нажмите F8, затем должна появиться фраза «Сцена очищена, значение сценария сохранилось». Можно выйти в меню до первого F8 и вернуться: активный запуск должен продолжиться с сохранёнными значениями.

Ключ NPC должен быть объявлен через `npc(...)` или `npc_instance(...)` в этом сценарии. При переименовании ключа добавьте `npc_state_migrate("старый_ключ", "новый_ключ")` перед чтением состояния нового NPC. Новый NPC должен быть объявлен в файле; старый объявлять не требуется. Действие переносит сохранённые переменные только внутри этого сценария. Если у нового ключа уже есть значения, они имеют приоритет; недостающие поля берутся у старого ключа, после чего старый набор удаляется. Повторный вызов безопасен; переход назад к якорю не возвращает старый ключ. Технический пример `900056.lua` создаёт старое значение и проверяет его перенос.

Эта миграция касается только переменных `npc:<key>`; она не переименовывает сущность NPC и не переносит её позицию. Удаление сценария пока не удаляет сохранённые значения NPC автоматически. Выдача предметов, управление камерой и другие побочные эффекты имеют собственные правила восстановления; эта область хранит только строки, числа и логические значения в текстовой форме.
